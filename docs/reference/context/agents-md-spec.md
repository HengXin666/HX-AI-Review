# AGENTS.md 规范

AGENTS.md 是 agent 进入仓库后读的第一个上下文文件: 它决定 agent 读什么, 不能做什么, 产物放哪. 本规范规定必选节, 每节的内容边界, 长度上限与决策的引用方式.

L0 目前只实现配对与长度 (HC-CONTEXT); 节结构由 CTX-001 判定, 判据与等级见 [validation.md](validation.md). 规范先于实现, 不把"未检查"写成"已通过".

## 适用范围

- 仓库根与子目录的 AGENTS.md 都适用; 子目录只写与父级的差异, 不复制父级正文.
- 同目录必须有 README.md, 双向配对, 缺失为 HC-CONTEXT Error.
- 本文件不写教程, 不写历史, 不复述决策.

## 必选节

| 节 | 必须回答 | 建议行数 | 缺节等级 |
|---|---|---|---|
| 定位 | 这是什么, 边界在哪, 改前先读什么 | 3-15 | error |
| 项目布局 | 目录职责, 路由规则, 归属索引 | 10-40 | warning |
| 共享铁律 | 必须遵守且可判定的硬约束 | 10-50 | error |
| 落盘 | 产物, 凭据, 文档分别去哪 | 5-20 | warning |
| 红线 | 禁止事项与决策引用方式 | 5-25 | error |

"缺节等级"只用于 CTX-001 的结构判定. error 级必选节不可豁免; warning 级节确无需求时, 必须在文件里写明原因, 否则按缺节处理.

### 定位

- 一句话说明仓库或模块是什么, 加 2-3 个首读链接, 再加一句"不做什么".
- 只写稳定事实: 语言, 运行形态, 对外边界. 不写版本号, 不写路线图, 不写"本文件用于..."的空话.
- 首读链接必须指向真实存在的文件, markdown 链接断链是 Error.

反例:

- "本仓库从 2024 年开始重构, 经历了三个阶段" -- 历史.
- "我们选择 D1 而不是 KV, 因为..." -- 决策, 应写进 note.

### 项目布局

- 用表格写 路径 / 职责 / 首读 三列; 一个目录一行, 不给每个文件建行.
- 写清路由规则: 什么任务进哪个目录, 读哪个 AGENTS.md.
- 新增目录必须在同一次改动里登记; 未登记的目录视为孤儿.
- 超过 40 行时把明细移到索引文件, 本节只留索引入口.

### 共享铁律

- 每条铁律 = 动作 + 判据 + 例外, 三样缺一不可.
- 判据必须能被检查或被复述: 命令, 阈值, 路径, 字段名.
- 禁止 "尽量", "注意", "合理", "适当" 这类不可判定词.
- 按主题分组 (环境, 验证, 安全), 不按时间或严重程度分组.
- 只写本仓库特有的约束; 通用规范链接到规范文件, 不复制正文.

### 落盘

- 产物: 路径模板, 含日期与归属占位, 例如 `out/<yy-mm-dd>/<topic>/`.
- 凭据: 写清哪些进仓库, 哪些只进忽略文件, 操作前用哪个命令查看.
- 文档: 事实进 reference, 原因进 decisions, 教训进 notes; 禁止建 v2 副本.
- 写清谁写谁读: agent 写人读, 还是 agent 之间交接.

### 红线

- 不可逆操作: 删除, 强推, 改历史, 生产写入, 以及各自的确认方式.
- 越权操作: 不该碰的仓库, 分支, 凭据, 环境.
- 决策内联: 决策只写在唯一的 note 中; AGENTS.md 必须引用该 note 的精确仓库路径, 不得复述结论.
- 泄密: token, cookie, 内网地址的存放位置与禁止出现的位置.

## 全局硬约束

| 约束 | 阈值 | 现有检查 |
|---|---|---|
| 行数 | 少于 150 行, 达到 150 行即 Error | HC-CONTEXT |
| 字节数 | 少于 16384 字节 | HC-CONTEXT |
| 配对 | 同目录有 README.md | HC-CONTEXT |
| 链接 | markdown 链接必须可达 | CX-DEADREF (Error) |
| 反引号路径 | 必须可达 | CX-DEADREF (Warning) |

"上限 150 行"指实现按 `lines >= 150` 报错, 所以实际最多写 149 行.

文件头 = 标题到第一个二级标题之间. 文件头只允许: 标题, 定位段, 首读链接; 定位段和首读链接必须出现在标题后的前 10 行. 出现决策, 历史, 变更记录即为违规.

## 决策的引用方式

决策只写在唯一的 note 中. AGENTS.md 只指向该 note 的精确仓库路径, 不复述结论; 每个代码目录选择一个代表文件, 并在目标声明顶部用多行注释反向引用同一个 note. note 的 `## Code` 逐行列出精确路径, 覆盖直接父目录; 禁止 glob、花括号路径和文件头占位引用.

错误:

```markdown
## 状态存储

我们决定用 D1 而不是 KV, 因为需要事务和 SQL 查询.
```

正确:

```markdown
## 状态存储

决策见 `.agents/notes/storage.md`; 改动 `context-cr/src/` 前先读该 note.
```

判断标准: AGENTS.md 的路径可定位 note, note 可逐行定位代码, 代码声明顶部又能反向定位同一 note; 三端任一缺失即不合格.

## 真实例子: HX-UI 根 AGENTS.md

来源: HX-UI 组件仓库根目录, 32 行, 未超限, 未复述决策. 节选如下, 省略 HTML 注释标记与部分链接细节, 保留节结构与要点.

```markdown
# HX-UI Agent 指引

项目概览, 组件清单与开发命令见 README.md. 本文件只放 Agent 必须遵守的约束.

## 质量门禁

- 改动完成后运行 `npm run quality:done`: 对最终工作区 diff 做静态检查, 再执行一次受影响测试. 有新增 Error 不得宣称完成
- 规则, 命令与豁免见 docs/reference/quality/rules.md; 规则逐项裁决见 scripts/quality/coverage.json
- baseline (scripts/quality/baseline.json) 只记录安装门禁前的历史违规, 不得为了让检查通过而新增或改写条目

## 硬约束

- 同一字面量在代码中出现 3 次及以上, 提取到 src/constants/ (库与文档站) 或 scripts/constants/ (脚本工具) 后引用
- 禁止任何文件系统绝对路径写法, 包括以根路径开头的路径拼接; 使用仓库相对路径或运行时解析
- 组件颜色只来自语义 token, 线条只用 1px, 不写 transition-all, 原生 button 必须写 type
- 脚本只写 .ts, 由 Node 22.18+ 直接运行, 不新增 .js/.mjs/.cjs
- 组件视觉类名沿用上游 open-vetta, 不在门禁类改动中顺手修改组件视觉或行为
- 改动前端功能的 PR 必须在正文嵌入 GIF 演示: 按 .agents/skills/record-browser-gif/SKILL.md 从 PR 头部 commit 构建文档站录制, 推到孤儿分支 pr-assets 的 pr-<编号>/ 下, 写明演示的 commit SHA, 内容与间隔 / 倍速; GIF 永不提交到 PR 分支. CI 工作流 pr-gif 检查, 没有可见变化时由维护者加 no-gif 标签豁免

## Agent Notes 红线

改声明前先读其顶部多行注释引用的 .agents/notes/...md. 每条决策只保留一篇 note, ## Code 逐行列仓库相对精确文件路径, 每个直接父目录只选一个代表文件, 在该文件的声明顶部反向引用该 note. 禁止 glob, 花括号和文件头占位引用

代码或 note 改动必须在同一 diff 配对, 同目录兄弟代码也算该决策的代码端. 单边改动必须 review, 不可用无关 note 或豁免文本放行. 过时事实就地改写, 废弃 note 直接删除并修复所有引用. ## Alternatives considered 必须包含什么都不做 / 复用现有, 每项先给最强理由再否决

完成改动运行 `uv run scripts/redlines/agent_notes.py --diff`, 全量调研用 --all, 提交前用 --staged. AST 必须支持 cpp/ts/tsx/js/mjs/go/py/rs, 缺依赖或解析失败即失败. 规则见 .agents/notes/AGENTS.md

受保护的非 AST 资源改动报告 resource-review, 由人工核对决策和引用

CI 工作流始终容错完成, 有问题时在对应代码片段评论并保存完整 JSON 诊断. CI 成功只表示流程完成, 双链是否有效以诊断内容为准. 本地校验仍用非零退出码暴露问题
```

| 必选节 | 对应内容 | 结论 |
|---|---|---|
| 定位 | 第 1-3 行 | 具备: 一句边界 + 指向 README |
| 项目布局 | 无 | 缺: 单包仓库, 目录简单, 按 warning 记录 |
| 共享铁律 | 质量门禁, 硬约束 | 具备: 命令, 阈值, 路径均可判定 |
| 落盘 | 无 | 缺: 无产物落盘需求, 按 warning 记录 |
| 红线 | Agent Notes 红线 | 具备: 决策引用与禁止 glob 写清 |

结论: 这是最小可用样例, 不是满分样例. 它用 32 行覆盖了 agent 最需要的三节, 把可推导的布局交给 README; 一旦仓库出现产物目录或第二个包, 必须补 项目布局 与 落盘.

## 提交前检查清单

- [ ] 少于 150 行且少于 16384 字节
- [ ] 同目录 README.md 存在
- [ ] 所有 markdown 链接与反引号路径可达
- [ ] 前 10 行没有决策, 历史, 变更记录
- [ ] 每条铁律都有动作, 判据, 例外
- [ ] 子目录 AGENTS.md 只写差异
- [ ] 决策只通过唯一 note 的精确路径引用, 代表文件声明顶部有反向引用
